# integrations — 外部サービスとの連携

スプレッドシート・社内API・チケット管理など、**外の世界とやりとりする機能**を
置く場所です。1フォルダ＝1連携で、`config.json` に書いたものだけが読み込まれます。

## 有効にする

```jsonc
// config.json
"integrations": { "enabled": ["example_notes"] }
```

さらに、使わせたいエージェントの `skills.<SKILL_KEY>` を true にします
（連携が `SKILL_KEY = "notes"` を宣言していれば `skills.notes`）。
**この二段階のゲートは意図的**です。連携を入れただけでは誰も使えず、
どのエージェントに持たせるかを明示的に選ぶことになります。

ダッシュボードの「外部連携」からも同じ操作ができます。

## 書き方

`integrations/<名前>/__init__.py` に、使いたいフックだけを定義します。
**定義しなかったフックは呼ばれません**（全部書く必要はありません）。

| フック | いつ呼ばれるか | 何をするか |
|---|---|---|
| `available(config)` | 読み込み時 | 使える状態か（APIキー未設定なら False） |
| `skill_note(ctx)` | 回答を作る前 | AIに「この道具の使い方」を教える |
| `context_block(ctx, gate_text)` | 回答を作る前・**別スレッド** | 回答の材料になる現況を渡す |
| `apply_markers(ctx, answer)` | 回答ができた後・**別スレッド** | AIが出したマーカーを実行する |
| `CYCLES` | 定期（既定30分ごと） | 定期処理。文字列を返すとホームchに投稿 |
| `PREHOOKS` | 発言のたび | 決定的トリガー。True を返すと通常応答を止める |

`ctx` は `chatbot/integrations.py` の `Context`（エージェントID・DBパス・
発言者・管理者かどうか等）。**Discord固有のオブジェクトは入っていません** —
将来 Slack などに載せ替えても連携が壊れないようにするためです。

まずは同梱の `example_notes/` を読んでください。APIキーもネットワークも
不要でそのまま動く見本で、上の表のうち3つのフックを実際に使っています。

## 大事なこと

- **やったことを必ず見せる**。マーカーを実行したら `-# ` 行で結果を返してください。
  これを省くと「保存しました」と言ったのに何も起きていない状態が生まれます。
  失敗したときも黙らず、失敗を返してください
- **例外を投げても大丈夫**。1つの連携の不具合でBOT全体は止まりません
  （ログに出して、その連携だけ無効になります）。ただし黙って握りつぶさないこと
- **`context_block` はゲートを書く**。関係のない会話のたびにAPIを叩かないよう、
  `gate_text`（今の発言＋直近の会話）を見て関係なければ `None` を返してください
- **秘密はconfigに置く**。連携のコードにAPIキーを直書きしないでください。
  `config.json` に書いて `ctx.config` から読むか、環境変数を使ってください

## Git の扱い

`integrations/` の中身は `example_*` と この README 以外 **追跡されません**。
自分の会社用の連携が誤って公開されないようにしてあります。
チームで共有したいときは、その連携だけ別のプライベートリポジトリにして
ここに置く（またはシンボリックリンクを張る）のがおすすめです。

## `plugins`（`chatbot/tools/`）との違い

似た仕組みが2つあります。

| | integrations（ここ） | plugins（`chatbot/tools/`） |
|---|---|---|
| 誰が書く | 人間 | AI（開発BOT）も書ける |
| import | 制限なし | `os` / `subprocess` / `socket` 等は**禁止**（AST検査） |
| 向いているもの | 外部サービス連携 | 計算・整形など閉じた道具 |

ネットワークを使うものは必ずこちら（integrations）に書いてください。
