# 困ったとき

## まず見るところ

**ダッシュボードの「運用」画面。** 各BOTの状態・稼働時間・再起動回数が出ます。
再起動回数が増え続けていれば、起動に失敗し続けています。

**ログ。** `state/logs/` に入っています。運用画面からも読めます。

| ファイル | 中身 |
|---|---|
| `state/logs/archivebot.log` | 会話エージェント |
| `state/logs/devbot.log` | 開発BOT |
| `state/logs/meetingbot.log` | 議事録BOT |
| `state/logs/supervisor.log` | 常駐プロセス（自動起動したとき） |

---

## セットアップ（start.py）が失敗する

### 「管理画面の準備に失敗しました」

エラーの詳細が画面に出ます。全文は `state/logs/setup.log` にもあります。

よくある原因の順に:

**1. リポジトリが古い。** 最新のNode（26以降）で部品のコンパイルが
失敗する問題は修正済みです。`git pull` してから
`rm -rf dashboard/node_modules` で作り直してください。

**2. Xcode Command Line Tools が無い（mac）。**
`xcode-select --install` を実行してください。
「already installed」と出るのに失敗する場合は、
`sudo xcode-select --reset` か、macOSアップグレード後なら入れ直しを:

```bash
sudo rm -rf /Library/Developer/CommandLineTools && xcode-select --install
```

**3. ネットワーク** — プロキシ環境では npm の設定が必要なことがあります。

**4. Node.js のバージョン** — 20以上が必要です。うまくいかないときは
LTS版（22/24）が最も確実です: https://nodejs.org/

手で試して切り分けることもできます:

```bash
cd dashboard && npm ci
```

## Botがオンラインにならない

### `Improper token has been passed.`

トークンが違います。Developer Portal の **Bot** ページで Reset Token を押し、
新しいものをダッシュボードから登録し直してください。
Client Secret（OAuth2ページのもの）ではありません。

### 「常駐プロセス（run.py）に接続できません」

`python run.py` が動いていません。ターミナルで起動するか、
[自動起動](05-autostart.md)を設定してください。

### 「設定が足りないため起動できません」

足りない項目が並んで表示されます。`python start.py` でダッシュボードを開いて
設定してください。

---

## オンラインなのに反応しない

### 話しかけても無視される

**ほぼ確実に MESSAGE CONTENT INTENT が入っていません。**
[01-discord-bot-setup.md の手順3](01-discord-bot-setup.md) を確認してください。
オンにして保存したあと、BOTの再起動が要ります。

次に多いのは:

- **ホームチャンネルが違う** — 「エージェント」画面で確認してください
- **「呼ばれた時だけ答える」がオン** — その場合は `@名前` で呼んでください
- **他のエージェントが名指しされている** — 譲り合う仕様です

### 少し前まで動いていたのに止まった

イベントループが詰まっている可能性があります。常駐プロセスが生存証明の
鮮度を見て自動で再起動しますが（既定5分）、待てない場合は運用画面から
再起動してください。

---

## 答えの中身がおかしい

### 「記録が見つかりません」しか返ってこない

会話の蓄積がまだ足りません。**BOTが起動する前の会話は、遡って取り込まれます**が、
初回起動の直後は取り込みに時間がかかることがあります。
ログに `backfilling guild:` と出ていれば取り込み中です。

### 事実と違うことを言う

エージェントは**過去ログに書かれていること**を根拠に答えます。
チャットに間違った情報が残っていれば、それを引用します。

`knowledge/` に前提知識を置くと、そちらが優先されます。
[02-configuration.md](02-configuration.md) の `persona_files` を参照してください。

### 返事が長すぎる／口調が気に入らない

「性格」画面で性格ファイルを直してください。**返信の長さは明示的に書く**のがコツです
（書かないと毎回長文になります）。保存すれば次の回答から反映されます（再起動不要）。

---

## 自分から話しかけてくれない

観察ループが既定でオフです。「全体設定」で有効にしてください。
ただし:

- **まずシャドーで動かす**ことをおすすめします（記録だけして発言しない）
- **1日の発言回数に上限があります**（既定3回）。使い切ると翌日まで黙ります
- **深夜は休みます**（既定23時〜8時）

---

## AIが応答しない

### 「〜が見つかりません」

Claude Code / Codex CLI がインストールされていないか、PATH が通っていません。
[04-llm-providers.md](04-llm-providers.md) を参照してください。

launchd やタスクスケジューラから起動するとPATHが最小限になります。
よくある置き場は自動で探しますが、それ以外なら設定に絶対パスを書いてください。

### 「出力が空でした」

AIツール側のログインが切れている可能性があります。
そのツールを手で1回実行して、認証が通るか確かめてください。

### 添付ファイルを読んでくれない

**Claude Code 以外では添付の読解ができません。** 「全体設定」の
「使うAI」に、使えない機能が表示されます。

---

## 動きが重い

`max_concurrent_answers` を下げてください（既定2）。
AIの同時実行数なので、多いとPCが重くなります。

観察ループの `interval_min` を伸ばすのも効きます。

---

## それでも分からないとき

Issue を立てるときは、次を添えてもらえると原因が早く分かります。

- OS（macOS / Windows）とバージョン
- `state/logs/` の該当ログ（**トークンが混ざっていないか確認してから**）
- ダッシュボードの「運用」画面のスクリーンショット
