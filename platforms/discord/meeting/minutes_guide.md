# 議事録作成ガイド

Discordボイスチャンネルの録音から文字起こしされたトランスクリプトを元に、Slackへ投稿する議事録を作成する手順。

## 入力データ

### トランスクリプトの形式

```
[MM:SS] ユーザー名: 発言内容
```

- faster-whisper（smallモデル、日本語）による音声認識
- 各発言者ごとに別トラックで録音されているため、同じタイムスタンプに複数の発言が並ぶ
- 認識精度にばらつきがあり、固有名詞や専門用語の誤認識が多い

### 補足情報

- 開始時刻・終了時刻: ディレクトリ名（`YYYYMMDD_HHMMSS`）とトランスクリプトの最終タイムスタンプから算出
- 参加者: トランスクリプトに登場するユーザー名を収集

## 作成手順

### ステップ1: 全文の通読と会話の分離

トランスクリプトを最初から最後まで通読し、以下を把握する。

1. **並走する会話の識別**: 複数人が同時に別の話題を話している区間を特定する。特に会議冒頭は全員が揃う前に雑談や別トピックが並走しやすい
2. **話者のグルーピング**: 同じタイムスタンプ帯で誰と誰が会話しているかを追跡する。返答の文脈（相槌、質問への回答）から判断する
3. **退出・入室のタイミング**: 「お疲れ」「お疲れ様です」などの挨拶で参加者の出入りを把握する

### ステップ2: 音声認識の誤り補正

文脈から誤認識を推測し、正しい語句に置き換える。

よくある誤認識パターン:
- 固有名詞の誤変換（社名・製品名・人名は、前後の文脈から正しい表記に直す）
- 同音異義語（例: 「記事録」→「議事録」、「以降」→「移行」）
- フィラー（「えー」「あー」「うん」「はい」）は無視する
- 断片的な発言（1〜2語で意味が成立しない短い相槌）は文脈把握のためだけに使い、議事録には含めない
- 複数話者の発言が混ざった認識結果に注意する

補正時の注意:
- 不確実な補正は行わない。意味が取れない箇所は省略するか、前後の文脈から推測可能な範囲にとどめる
- 発言者の意図を変えない。客観的事実のみを記載し、作成者の解釈を加えない

### ステップ3: トピックの抽出と構造化

通読した内容から、議論されたトピックを時系列で抽出する。

1. **話題の切り替わりを検出する**: 「次の話」「あと」「で」「じゃあ」「えっと」などの接続詞、または明確な話題転換を目印にする
2. **各トピックについて以下を整理する**:
   - 何についての議論か（議題名）
   - 背景・経緯
   - 出された意見・提案
   - 問題点・課題
   - 結論（決まったこと / 決まらなかったこと）
   - 次のアクション（誰が・何を・いつまでに）
3. **並走していた会話は関連性で統合する**: 同じトピックについて別グループが議論していた場合はまとめる。無関係な場合は別トピックとして分離する

### ステップ4: 決定事項とアクションアイテムの抽出

トピック整理とは別に、会議全体を通して明確に合意・決定されたことと、具体的なタスクを抽出する。

**決定事項の判定基準:**
- 「じゃあそれで」「それでいきましょう」「やりましょう」など、合意の表現がある
- 複数人が同意している
- 具体的な方針や手順が確定している

**アクションアイテムの判定基準:**
- 「〜を作る」「〜に連絡する」「〜を確認する」など、具体的な行動が示されている
- 担当者が明示的または文脈から特定できる
- 期限が言及されている場合はそれを記載。なければ「来週中」「早急に」など文脈から推定する

### ステップ5: 出力の構成

以下のセクション構成で議事録を作成する。

```
1. ヘッダー（日付、時間、参加者）
2. サマリー（会議全体を1〜3行で要約）
3. 議題と議論（トピックごとに構造化）
4. 決定事項（合意されたことのリスト）
5. アクションアイテム（担当者ごとにグルーピング）
6. 次回予定
```

**サマリーの書き方:**
- 会議で扱った主要トピックを列挙し、全体像を1〜3行で伝える
- 読み手がこの部分だけ読めば会議の概要がわかるようにする

**議題と議論の書き方:**
- トピックごとに見出しをつけ、箇条書きで整理する
- 1つの箇条書きに1つの情報を原則とする
- サブ項目がある場合はインデントで階層化する
- 並走した会話があった場合は注記を入れる
- 手順やフローは番号付きリストで記載する

**アクションアイテムの書き方:**
- 担当者ごとにグルーピングする
- 各タスクにチェックボックスと期限を付ける
- 担当者名はSlackメンションに変換する。対応表は `config.json` の `user_mapping`
  （Discordの表示名 → SlackメンバーID）から読み込む。例:

  ```json
  "user_mapping": {
    "yamada": "<@U01234567>",
    "suzuki01": "<@U89ABCDEF>"
  }
  ```

## 出力フォーマット（Slack mrkdwn）

Slackに投稿するため、Slack独自のmrkdwn記法を使用する。

### 記法対応表

| 要素 | Markdown | Slack mrkdwn |
|------|----------|-------------|
| 見出し（大） | `## テキスト` | `*テキスト*` |
| 見出し（小） | `### テキスト` | `*テキスト*` |
| 太字 | `**テキスト**` | `*テキスト*` |
| イタリック | `*テキスト*` | `_テキスト_` |
| リスト | `- ` | `• ` |
| サブリスト | `  - ` | `    ◦ ` |
| 番号付き手順 | `1. 2. 3.` | `① ② ③` |
| 引用 | `> テキスト` | `> テキスト` |
| コード | `` `テキスト` `` | `` `テキスト` `` |
| テーブル | `\| col \|` 形式 | 非対応。リスト形式に変換 |
| 区切り線 | `---` | `━━━━━━━━━━━━━━━━━━` |
| チェックボックス（未） | `- [ ]` | `☐` |
| チェックボックス（済） | `- [x]` | `☑` |

### テンプレート

```
*【定例会議】YYYY/MM/DD (曜日)*

*開催時間:* HH:MM - HH:MM（約XX分）
*参加者:* ユーザー名1, ユーザー名2, ...

*サマリー*
> 会議の要点を1〜3行で記載。

━━━━━━━━━━━━━━━━━━

*議題と議論*

*1. トピック名*
• 論点や背景
    ◦ 詳細
    ◦ 詳細
• 結論や方向性

*2. トピック名*
• ...

━━━━━━━━━━━━━━━━━━

*決定事項*
☑ 決定1
☑ 決定2

*アクションアイテム*

<@SlackメンバーID>
  ☐ タスク内容（期限）
  ☐ タスク内容（期限）

<@SlackメンバーID>
  ☐ タスク内容（期限）

*次回予定*
• 日時と内容
```

## 品質チェックリスト

作成後に以下を確認する。

- [ ] サマリーだけ読んで会議の概要がわかるか
- [ ] 各トピックの結論が明確か（決まった / 決まっていない / 保留）
- [ ] アクションアイテムに担当者と期限があるか
- [ ] 並走していた会話が正しく分離・統合されているか
- [ ] 音声認識の誤りが放置されていないか
- [ ] 主観的な解釈が混入していないか
- [ ] 機密情報（SNSで公表しない内容など）に注記があるか
- [ ] Slack mrkdwn記法が正しいか（`**` ではなく `*` など）
